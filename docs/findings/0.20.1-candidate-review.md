# Core 0.20.1 candidate review

**Status: implementation candidate, not a release approval.** This candidate is
local commit `28ed70cc31175333228412c7d90ecb4594f54f37`, descended from the
0.20.0 candidate `b30433c9577fe2493072e442b0f4ea307f342fcf` via a local merge.
It identifies itself as version 0.20.1. The candidate was installed from local
Git for Bench, so this is not an official-origin release verification. No tag
or package was published.

It implements the retrieval-local feature/lookup optimizations, SQLite scoped
semantic reads, and correction/withdrawal history fix described in the
[development findings](0.20.1-scoped-sqlite-read.md). The chosen source contract
reports both a correction and the later withdrawal. Runtime behavior is the same
as the previously tested development commit `73b4a75` except for the version
string; the merge also brings in 0.20.0 profiling and documentation changes.

## Versioned-candidate performance measurements

Using the same sequential, uninstrumented 2018 Mac protocol (100 warm samples
following the first for the smaller sizes; 100 samples including the first for
1,000), the versioned candidate measured:

| Base observations | Backend | Warm median | Nearest-rank p95 at 1,000 |
| --- | --- | --- | --- |
| 100 | Memory | 0.087 s | — |
| 100 | SQLite | 0.130 s | — |
| 250 | Memory | 0.221 s | — |
| 250 | SQLite | 0.326 s | — |
| 1,000 | Memory | — | 1.329 s |
| 1,000 | SQLite | — | 2.919 s |

SQLite failed the selected p95 under-two-seconds target in this run even though
its earlier equivalent-code development run measured 1.825 s. The slowest
candidate samples cluster early and show increased process CPU and non-CPU wall
time. This is consistent with contention, but no process-level evidence
establishes a cause. The machine was not isolated and OS caches were not
controlled; do not discard this result or infer a cold-device guarantee. A second complete SQLite run measured 1.955 s p95 (median 1.806 s); the first
measured 2.919 s p95 (median 1.847 s). Both runs are retained, so the candidate
did not establish consistent performance below the target. Raw samples are named
`0.20.1-candidate-{memory,sqlite}-{100,250,1000}.json`; the second SQLite
run is `0.20.1-candidate-sqlite-1000-repeat.json`.
