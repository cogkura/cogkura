## Weight sweep

Effective semantic contribution scales as `λsem × Rₛ` where `Rₛ = ΣRⱼ/K`.

| Scenario | `Rₛ` | `λsem=0.25` | `λsem=0.50` | Notes |
|----------|------|-------------|-------------|-------|
| Context-specific (all supports match) | `1.0` | `0.25` | `0.50` | Rank/threshold improves vs `λsem=0` |
| Cross-context (4 domains, 1 perfect) | `0.25` | `0.0625` | `0.125` | Bounded dilution from unrelated supports |
| Sparse legacy (2 perfect, 8 unavailable) | `0.2` | `0.05` | `0.10` | Unresolved supports count in `K` |
| All mismatch | `0.0` | `0.0` | `0.0` | No penalty |
| Max-support forbidden (1 perfect, 19 mismatch) | `0.05` | `0.0125` | `0.025` | Prevents single-match dominance |

Sweep `{0.25, 0.50, 0.75, 1.00} × episodic default context weight` considered relative to episodic default `0.50`:

- `0.25` restores context-specific semantic rank lift on tested fixtures without admitting unrelated semantics in adversarial relevance test.
- `0.50` doubles semantic lift but remains ≤ episodic default; acceptable when semantic/context alignment is strong.
- Larger weights increase cross-context dilution risk on multi-domain support sets.

**Frozen default:** `semantic_context_reinstatement_weight=0.25` (smallest useful weight ≤ episodic `0.50` on in-repo fixtures).

## Engineering note

`semantic_context_reinstatement_weight` is an in-repo engineering calibration, not a cognitive-science constant. No-context workloads and `weight=0` preserve `0.16.2` semantic retrieval behaviour aside from additive diagnostic fields.
