# 0.17.7 interference and inhibition architecture freeze

**Decision: the `0.17` interference and inhibition architecture is frozen at the `0.17.6.1` retrieval contract.**

No formula, weight, eligibility, default, or schema change shipped with this release. `apply_interference` and `apply_to_recall` stay off.

## Suite

[`tests/test_interference_inhibition_architecture_freeze.py`](../tests/test_interference_inhibition_architecture_freeze.py) locks the frozen boundaries:

- Diagnostic competition can exist while `scope_eligible` is false, with zero transient penalty and no induction permission.
- Proactive and retroactive penalties are both reachable, including both directions in one retrieval. Co-temporal stays scope-eligible and penalty-free.
- A different predicate, a different service, an unrelated high-accessibility memory, and a semantic with its own support episode do not suppress one another.
- Presentation APIs write no traces. `record_access` can. Consumed versus reinforcement stays split under burst limiting and `min_score`.
- Exact co-consumption, semantic/support co-consumption, and a third unconsumed competitor. Same slot is not consumption.
- Scope-matched persistent penalty, zero penalty on a different predicate, monotonic recovery, repeated use, and re-selection that does not delete history.
- Persistent inhibition runs before transient interference. `ActivationComponents.inhibition` stays separate from the transient penalty. Both are `<= 0`.
- `valid_at` hides future facts. `as_of` hides future traces. A current `as_of` can inhibit a historically valid memory.
- Superseded cardinality-one semantics stay out of current authority. Forgetting is not written by interference. Reinforcement and inhibition are separate records from one use.
- Context reinstatement stays upstream. Working memory still receives ordinary `RecallResult`s. Inspect and assess agree on `interference`, write nothing, and still report a threshold-suppressed candidate.
- Both behavioural switches off: activations match the non-behavioural path, and retrieval does not call `InhibitionStore.list_for_memories`.

Shuffled consumed order and a second identical recall match on identities, penalties, and trace decisions. Trace UUIDs are not part of that equality.

The PostgreSQL case in [`tests/test_postgres_inhibition_store.py`](../tests/test_postgres_inhibition_store.py) applies a stored trace during recall when `apply_to_recall` is true and does not when it is false. It skips unless `COGKURA_POSTGRES_MEMORY_URL` is set. Co-consumption stays in the in-memory suite.

## Known limits

- Diagnostic competition is broader than behaviour. A diagnostic relationship does not authorize a penalty or a trace.
- `transient_interference_v1` is historical. It is not a freeze failure.
- Defaults stay off. Enabling either switch is an application choice, not the frozen default.

## Bench

CogKuraBench was not rerun from this repository. The evidence already recorded for this line:

| Workload | Result |
| --- | --- |
| Transient v2 controlled gate | precision and recall `1.000` |
| Persistent controlled gate | precision and recall `1.000` |
| Broader workloads | trace and effect precision and recall `1.000` |

Those runs reported no returned-set changes, no ordinary threshold suppression, small rank movement, modest traces, and flat latency.

## After the freeze

Compaction, automatic deletion, cancellation, default-on application, and adaptive or model-based competition stay deferred. A behavioural change needs a new design note.
