# 0.20.0 profiling release preparation

**Status: in progress; not a release approval.** This checkout separates the
0.20.0 investigation from the 0.20.1 implementation. Core's runtime source is
the 0.19.6 implementation apart from its version metadata; the optimized and
history-fix implementation remains in the separate `cb52362` commit. This
release does not claim that retrieval has been optimized or that the historical
withdrawal defect has been fixed.

## Root cause and investigation

The [initial profile](0.20.0-retrieval-profiling.md) found repeated episode
feature construction within associative matching. At 100 observations and five
observation revisions, it recorded 48,500 episode-feature calls; at 250, it
recorded 308,750. A later [profile](0.20.0-scaling-followup.md) identified a
separate repeated linear lookup during semantic admission after the earlier
optimization experiments. Inclusive profiler times overlap and are not additive.
The independent experiments are evidence for 0.20.1, not changes in this
candidate.

The profiling scripts add no Core runtime instrumentation. `profile_retrieval.py`
can separately record cProfile, coarse stage timings and loaded object counts,
Python allocation changes, or SQLite statement counts. It can use memory,
SQLite or a **disposable** PostgreSQL database. `profile_fresh_process.py`
reopens a prepared SQLite fixture in separate Python processes and compares the
first and second recalls. `run_software_project_workload.py` retains its original
fixture and also supports heterogeneous incident descriptions and independently
varied relationship counts. The fixtures remain synthetic; they are not a
representative Agent corpus.

## New baseline observations

The user selected this Mac as the reference system because another system is not
available: MacBookPro15,2, Intel Core i5-8259U at 2.30 GHz, 8 GiB RAM and eight
logical CPUs, macOS 15.8.1 (24H32), CPython 3.11.15 and SQLite 3.53.1. The host
root filesystem is APFS on solid-state storage; the checkout's filesystem was
not separately verified. The host is not isolated and OS caches are uncontrolled.
PostgreSQL comparisons use a disposable local PostgreSQL 14.18 instance.
The following individual
diagnostic observations are not an accepted production p95; timings and loaded
counts are not a mutually exclusive decomposition.

The user also selected the proposed **p95 under 2 seconds at approximately 1,000
observations** as the later optimized-release target on this Mac. For a
reproducible controlled check, use the unchanged mixed workload with 1,000 base
observations and five observation revisions, and report memory and SQLite
separately. This fixture adds six correction/withdrawal observations, so it has
1,006 actual observations and 5,006 observation revisions. PostgreSQL is an
additional comparison, not a requirement to beat
SQLite. For the controlled p95 calculation, run at least 100 uninstrumented
queries from the fixture's fixed sequence per backend, include the first recall,
retain each observation, and use the nearest-rank p95. Report host activity and
process/cache conditions; 100 queries are a practical minimum, not a confidence
interval or a cold-device study. This
synthetic reference is not a claim about production Agent workloads. The
user also selected **median warm recall under 1 second at 100 observations**
and **under 1 second at 250 observations** on this Mac. Use five observation
revisions per base observation and report the backends separately; measure the
median of at least 100 fixed-sequence queries after the first recall, retaining
all individual samples including that first query. The
0.20.0 baseline is not expected to meet the later optimization targets.

Stage timers are nested; async store calls can overlap. `returned_items` counts
returned Python collection elements, not bytes or unique database rows. SQLite
statement tracing counts SQL executed on its worker; it does not measure disk
I/O. Peak process RSS includes fixture construction and uses OS-specific units.
The 1,000/1 runs have matching fixture counts, operation counts and rounded
ranked outputs across all three backends. The same counts, operations and
rounded ranks also match across the 1,000/5 baseline runs. These are not exact
Bench fingerprint comparisons.

## Open release requirements

- Refine representative Agent workload coverage; the controlled mixed fixture
  is a synthetic reference, not an actual Agent corpus.
- Complete the controlled baseline and identify any still-unmeasured matrix
  dimensions, including sufficient uninstrumented samples for a meaningful
  tail estimate and any cold-device limitation.
- Complete the clean candidate's independent frozen and backend comparisons,
  candidate-specific review of the inherited `ac-q-c20` and support-order
  differences, required compatibility checks and packaging validation.
- The 0.19.6 history workload with a correction followed by a withdrawal still
  fails before the correction was known. The workload must report that failure;
  its separately reviewed fix is planned for 0.20.1. See the
  [history investigation](0.20.0-history-correction-investigation.md).

Do not publish a tag or package solely on the evidence here.
