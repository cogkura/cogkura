# 0.20.1 development: scoped SQLite semantic reads

**Status: development evidence; not a release acceptance.** Core remains at
version 0.19.6 in the development checkout. The original optimized and history
fix implementation was `cb52362`; this investigation first added the 0.20.0
profiling tools in `dee98dc38abcb6d262b43db608b7ab809d162bfc`, then added the

## Change and measurements

A stage diagnostic on 1,000 base observations and five observation revisions
showed three semantic-list calls together taking 0.527 s during one 2.026 s
SQLite recall. Timers are inclusive and can overlap. SQLite had hydrated all
memories, revisions and relations for each list operation. Current-memory
reads now omit revisions; unscoped revision reads omit memories and their child
evidence; both omit relations. Historical memory reads retain both memories and
revisions, and subject-filtered revision reads retain memories. Writes still
hydrate the complete inventory. Filtering, ordering and a single read
transaction remain delegated to the existing logic.

The same user-selected 2018 Mac and fixed mixed fixture described in the 0.20.0
release preparation were used. Runs were sequential, uninstrumented, on CPython
3.11.15 and SQLite 3.53.1; the host was not isolated and OS caches were not
controlled. `1,000` denotes 1,000 base observations plus six operations (1,006
actual observations and 5,006 observation revisions). The p95 uses nearest rank,
includes the first of 100 queries, and is not a production guarantee or cold
device measurement. All individual samples and rounded results are retained.

## Correctness and next gates

A new parity regression compares current, historical, inactive, limited and
subject-filtered SQLite reads with a full hydrated inventory. The focused SQLite
semantic suite passed 35 tests. Ruff, format and mypy passed; the full Core suite
without PostgreSQL passed 1,001 with 48 skips. The correction-then-withdrawal
history workload passes in both [memory](data/0.20.1-scoped-history-memory.json)
and [SQLite](data/0.20.1-scoped-history-sqlite.json), including before the
withdrawal was known. The PostgreSQL-memory-enabled Core suite passed 1,043 tests with 6 skips.

The 0.20.1 history correction has reviewed source and scoring consequences
against 0.19.6. The selected complete transition history uses the versioned v2
source fixture; this does not automatically approve the candidate's changed
frozen scoring fields. Final exact-candidate identity, release lineage,
independent benchmark review, full CI, packaging and release process remain.

CPython 3.12.13. All 393 frozen query fingerprints, aggregate non-latency

and source assessments match that candidate in memory, SQLite, reopened SQLite
