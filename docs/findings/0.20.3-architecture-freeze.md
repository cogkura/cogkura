# Core 0.20.3 architecture-freeze audit

**Status: audit started; architecture is not frozen.**

The proposed freeze preserves the provider-neutral `Memory` facade and the
embedded SQLite ownership model; it does not add Agent, MCP or project-name
resolution dependencies. Existing Core interfaces cover the proposed basic
lifecycle, with the selective-consumption qualification in
[Agent readiness](0.20.3-agent-readiness.md). An installed 0.20.2 wheel has
passed an initial public-API restart test; this does not validate a future
0.20.3 artifact.

The [invariant matrix](0.20.3-invariant-matrix.md) inventories existing tests,
not candidate-specific proof. [Scoped processing](0.20.3-scoped-processing.md)
identifies both timestamp-only history growth on an unchanged selected subject
and a shared-claim case requiring tenant-wide consolidation. The
[scoped-read scaling investigation](0.20.3-scoped-read-scaling.md) records the
accepted measured initial-Agent envelope and the decision to defer compaction;
exact-candidate validation and broader operating claims remain outstanding.

Historical reconstruction depends on retained, compatible state; it does not
promise reconstruction of missing legacy snapshots or a coherent cross-store
snapshot during arbitrary concurrent writes. `HistoricalStateUnavailableError`
reports detected unavailable states, not every possible missing-history case.
`Memory.process()` orchestrates multiple operations and is not a single atomic
transaction. Embedded SQLite uses a local file; WAL on network filesystems and
automatic database encryption are outside the supported contract. PostgreSQL
remains optional. Reference-workload timings are not production SLAs.

The exact-candidate cognitive and backend validation, independent benchmark,
performance decisions, packaging, release review and version-pinned handoff all
remain open. Consult the [release status](0.20.3-release.md) for the gates.
