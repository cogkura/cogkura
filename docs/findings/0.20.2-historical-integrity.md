# 0.20.2 historical integrity

**Status: in progress.** This is not a complete historical reconstruction or
release acceptance claim.

## Missing shared semantic history

The shared contested-evidence regression exercises in-memory, SQLite and
PostgreSQL storage with one semantic memory's retained history deliberately
removed or replaced by an incompatible snapshot payload. After an episode has
received later evidence, an earlier historical inspection neither restores the shared episode from incomplete semantic
history nor returns the later evidence. The persistent cases alter only the
selected tenant and semantic memory's snapshots. The targeted regressions passed locally on CPython 3.11.

The case verifies this particular detectable incomplete shared state; it does
not prove that every missing snapshot can be detected. The existing
[0.20.1 reconstruction design](0.20.1-historical-reconstruction-design.md)
describes the ordering, custom-store, legacy and concurrent-read boundaries.
A preliminary ordering check is not a read transaction. Additional corruption
forms, supported temporal scenarios and concurrency tests remain open.

## Controlled read/write interleavings

A regression pauses a historical `recall()` immediately after its ordering
check, then updates a shared episode with a later-time observation before the
read continues. In-memory, two independent SQLite connections, and PostgreSQL
all returned the prior result without the future text. A second controlled interleaving
writes backdated evidence after that check: the ordering status becomes
ambiguous, and a subsequent historical read raises
`HistoricalStateUnavailableError` on all three backends. The test deliberately
makes no guarantee about the already-started read: its initial check is not a
transactional snapshot, and the supported boundary still excludes arbitrary
concurrent mutation during historical reconstruction. These tests do not cover
all store operations, cross-process timing, or concurrent mutations beyond
these interleavings.

The in-memory and SQLite shared-evidence cases also replace the selected
snapshot payload with malformed JSON; they omit the incompatible shared episode
and do not expose later evidence. PostgreSQL's JSONB storage rejects malformed
JSON at the database boundary, so its corresponding test uses an incompatible
versioned JSON payload rather than malformed JSON.
