# 0.16.5 context hardening findings

**Fixtures:** [`tests/test_016_5_context_hardening.py`](../tests/test_016_5_context_hardening.py), [`tests/test_contextual_memory_architecture_freeze.py`](../tests/test_contextual_memory_architecture_freeze.py)

## CONTEXT_CONFLICT classification

| Scenario | Expected state | Reason |
|----------|----------------|--------|
| Single comparable candidate, strength `0` | `CONTEXT_CONFLICT` | `NO_CONTEXTUAL_MATCH` |
| Multiple comparable candidates, all strength `0` | `CONTEXT_CONFLICT` | `NO_CONTEXTUAL_MATCH` |
| Any positive match among plausible candidates | not `CONTEXT_CONFLICT` | — |
| No comparable encoding context | `CONTEXT_UNAVAILABLE` | `NO_COMPARABLE_CONTEXT` |

Prior `0.16.4` bug: zero positive matches could classify as `CONTEXT_SUFFICIENT` (single candidate) or `CONTEXT_UNDERSPECIFIED` (tied zeros). Fixed in `0.16.5` without activation changes.

## Semantic support count semantics

| Condition | `unavailable_support_count` | `reason` |
|-----------|----------------------------|----------|
| No retrieval context | `0` | `NO_RETRIEVAL_CONTEXT` |
| All supports unavailable under cue | `N` | `NO_COMPARABLE_CONTEXT` |
| Missing internal match cache | `0` | `NOT_EVALUATED` |

Prior `0.16.4` bug: no-context path set `unavailable_support_count = N`.

## Mixed semantic support conflict

When `matching_support_count > 0` and `conflicting_support_count > 0`, retrieval-level diagnostics may include `PARTIAL_CONTEXT_CONFLICT`. Canonical mixed fixture: `Rₛ = 0.375` unchanged (`tests/test_semantic_support_context.py`).

## Weight documentation

- Episodic default `0.50`: operational default; `0.25` smallest tested observable effect on in-repo fixtures.
- Semantic default `0.25`: selected relative to episodic default; not because it is the smallest possible coefficient in isolation.

Both are engineering calibration parameters, not cognitive-science constants.

## Architecture freeze

Following `0.16.5`, the 0.16 contextual-memory line is frozen. Future behavioural changes require explicit design rather than incremental 0.16.x tuning.
